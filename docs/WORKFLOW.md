# Workflow

Use this as the operating playbook for humans and AI agents.

## Resume a disconnected task

1. Open `STATUS.md` for the current state.
2. Open `docs/START_HERE.md` for the navigation order.
3. Open `docs/FILE_MAP.md` to find the owning files.
4. Check `git status --short` before editing so user changes are not overwritten.
5. Continue from the last concrete changed file, not from memory.

## Build flow

1. Brief enters the Studio.
2. Stack is auto-selected by `skyn3t/studio/stack_selector.py`.
3. App type and engine metadata are inferred from the brief + stack, unless UI/env overrides are set.
4. Config needs are detected by `skyn3t/agents/config_detector.py`.
5. Runtime settings UI is generated by `skyn3t/agents/config_ui_agent.py`.
6. The build manifest records stack selection, app type, engine, frozen layout profile, config, stages, proof, and verdict.

## Documentation rule

When a feature adds a new owner file or concept:

1. Update `docs/FILE_MAP.md`.
2. If it affects app style, update `docs/APP_TYPES.md`.
3. If it affects game/visual engines, update `docs/ENGINE_OPTIONS.md`.
4. If it changes behavior or state, add a short note to `STATUS.md`.

## Refreshing the map

Run:

```bash
python scripts/refresh_file_map.py
```

The refresher keeps `docs/FILE_MAP.md` aligned with the repo's current owner map.
