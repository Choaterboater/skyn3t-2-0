## 1. Executive Summary

Builds ship non-working apps because **the go/no_go verdict is decided entirely from build-time and structural signals and never actually runs the delivered app**. The verdict conjunction at `runner.py:1630-1636` ANDs only static checks (proof.passed, byte-substance, on-disk entrypoint, intent-text match, critic scan); the only stage that serves+renders an app (liveness) runs *after* the verdict and is non-gating by default (`settings.py:185`). The one build-time gate that could catch a broken dependency tree — proof_run's `npm install` — **soft-skips every install failure except `EINVALIDPACKAGENAME` as "offline" (`proof_run.py:1065-1069`)**, so ERESOLVE/E404/ETARGET trees certify `go/100`. The strict `build_verifier` that *would* catch them runs every build but **its verdict is never read** (`runner.py:1402`). Meanwhile codegen actively manufactures the failures — dual Next.js routers, hallucinated/`"latest"`/whitespace dependency pins — and the fix-loop **cannot edit `package.json`** (`code_improver.py:115`), so the dominant JS failure class is unrepairable. Add JS/TS tests that never execute, a score decoupled from the verdict that rewards `no_go` builds, and singleton agent state that leaks a stale `degraded` flag across builds, and the factory both ships broken apps as green *and* trains itself backward.

## 3. Top 5 — Detail

**#1 — npm-install soft-skip (`proof_run.py:1065-1069`).** In `_run_node_build`, a non-zero `npm install` is treated as a real failure *only* when the output contains `EINVALIDPACKAGENAME`/`Invalid package name`; every other class (ERESOLVE peer conflicts, E404/ETARGET nonexistent versions) returns `(False, False, "npm install failed (offline?) — build skipped")`. Because `ran=False` is a soft skip (`proof_run.py:703-715` sets `detail['build']='skipped'` and never touches `passed`), `proof.passed` stays `True` for a tree that cannot install. This is the proximate reason build `c60c2d21` (3d-model, `@react-three/fiber@8.15.21` + nonexistent `openscad-openjscad@0.0.18`) certified `go/100` — reproduced live: the registry was reachable (E404, not offline) yet the failure was labeled offline. **Minimal fix:** invert the policy — non-zero install is a real failure `(True, False, out)`; soft-skip only when output carries genuine connectivity codes (`ENOTFOUND/ECONNREFUSED/ETIMEDOUT/EAI_AGAIN/getaddrinfo`). This single change makes `proof.passed` reflect real installability and feeds the fix-loop with real text.

**#2 — Verdict never runs the app (`runner.py:1630-1636`).** Every conjunct in the go-gate is compile-time/structural: `proof.passed`, `delivered_nonempty`, `substantive`, `has_entry`, `intent_ok`, `critic_gate`, `not scaffold_stub`, `not code_degraded`. None serves the app or asserts a 2xx render. The only stage that actually executes it, `_run_liveness`, is invoked *after* the verdict (`runner.py:1669-1671`) and by default (`liveness_gates_verdict=False`, `settings.py:185`) merely dampens score. So a bundle that compiles but throws on mount, or a Next route that crashes on hydration, satisfies every gate and ships `go`. **Minimal fix:** add a mandatory runtime smoke before line 1630 — for web stacks `AppRunner.start` → GET `/` → require 2xx + non-trivial post-render body (vision screenshot when available) — and AND its boolean into the verdict; reuse liveness but consult `outcome.passed`, gating on root-route dead + visual fail to avoid 405/SPA false positives.

**#3 — Fix-loop can't edit package.json (`code_improver.py:115`).** The fix-loop *does* feed real npm/tsc output back as a repair gap, but `_targets_from_gaps` selects files with regex `[\w./-]+\.(?:jsx|tsx|js|ts|py|css|html)` — `.json` is absent — so it never targets `package.json` and falls back to source entrypoints (`code_improver.py:120`), rewriting `App.jsx`, which has nothing to do with a dependency conflict. The same proof failure recurs each round until `max_attempts` exhausts → forced `no_go`. This makes the dominant JS failure class (whitespace keys, bad versions) structurally unrepairable, and `validate.py:50` confirms `.json` is otherwise a legal editable source type. **Minimal fix:** add `json` to the regex alternation, append the literal `package.json` token to BUILD-FAILED gaps carrying npm error codes, and add a deterministic `package.json` sanitizer in `_deterministic_fix` (trim whitespace dep keys, drop bad names) so the fix needs no model round-trip. *(Avoid the report's "drop `latest` pins" — `reconcile_npm_deps` writes `latest` intentionally; stripping it regresses valid builds.)*

**#4 — build_verifier's strict verdict is discarded (`build_verifier.py:237-246` / `runner.py:1402`).** `BuildVerifierAgent` runs a real `npm install --no-audit --no-fund` and returns `verdict="fail"` on any install failure — it *would* catch `c60c2d21`'s ERESOLVE. But its output lands only in `prior['verify_build']`; the runner's `prior.get(...)` reads are exclusively architect/code/critic, and the verdict gate has no verifier term. `is_verifier`/`VERIFIER_TYPES` (`stages.py:18-26,60`) are defined but never called. Net: two install paths with inconsistent semantics (strict verifier vs lenient proof_run) and only the lenient one decides delivery, so the strict result + reward-hacking detection are cosmetic manifest data, costing a full duplicate npm install per web build. **Minimal fix:** do *not* blindly AND the raw verdict into the gate (it can't distinguish ERESOLVE from a flaky/offline registry and would regress valid offline builds). Instead, fold the strict install **classification** into proof_run (#1's fix) and delete the redundant contract/build/boot verifier stages — one authoritative, network-aware install gate.

**#5 — JS/TS tests are never executed (`proof_run.py:956-969`).** `_run_generated_tests` is the only test path and runs only pytest: `is_python = low in ("cli","python","fastapi","flask","django")`, and `_has_python_tests` scans `.py` only, so react/nextjs/astro/remix/express tests soft-skip with the comment "node/web tests need an install step we skip." Separately `_run_node_build` runs the `build`/`typecheck` script but never `test` (`proof_run.py:1049`). Authored `.test.tsx`/`.spec.js` files therefore contribute zero behavioral validation while still earning checklist/substance credit (`.ts`/`.tsx` are in `_SOURCE_SUFFIXES`) — the `settings.py` docstring even promises "npm test … fails the proof," which is unimplemented. **Minimal fix:** after a successful `npm install`, if a `test` script and a runner (vitest/jest) are present, run it non-interactively (`CI=1`, vitest `--run`) and gate on it — mirroring pytest, but reusing pytest's soft-skip nuance (rc=5/ModuleNotFound → skip) so jsdom/canvas-env failures don't false-fail valid builds. As a fallback, stop crediting un-run test files toward substance/coverage.

## 4. Recommended Fix Order

Do these in sequence for the biggest reliability win per unit effort:

1. **`proof_run.py:1065-1069` install-failure classification (#1)** — the single highest-leverage change. It flips the large class of false `go/100` (un-installable trees) to honest failures and *activates the fix-loop* for them. Pair the small `package.json` sanitizer here.
2. **`code_improver.py:115` + deterministic dep sanitizer (#3, #11)** — without this, #1 only converts false-go into `no_go`; this lets the loop actually repair the dep failures it now sees. These two together close the whole "broken `package.json` ships or dies" cycle.
3. **Codegen source-side pins (#7, #8, #16)** — stop manufacturing the failures: pin a single Next.js router + normalize, add `nextjs` to `_JSX_STACKS`, and resolve dependency versions against the registry. Reduces fix-loop churn.
4. **Runtime-execution gate (#2, #6, #19)** — make liveness/serve+fetch a hard conjunct (default-on for web, root-route + visual gated) so compile-success no longer equals delivery. Then collapse the redundant strict verifiers (#4).
5. **Vocabulary + integrity cleanups (#10, #12, #17, #25)** — add astro/remix to `_WEB_STACKS`, fix the singleton `degraded` leak (one-line `pop` at `execute()` entry), clamp score on `no_go`, and scope `reconcile_orphaned_builds`. Each is small and stops a distinct false-no_go / backward-training source.
6. **Test/config theater (#5, #13, #14, #20-24)** — execute JS/TS tests, route/wire the Settings UI, fix the verifier label mismatches.
